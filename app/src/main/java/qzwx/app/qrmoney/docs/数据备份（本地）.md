# 数据备份（本地）开发说明文档

> QRMoney Android 项目（Compose + Material3 + Hilt + Room + Navigation3）的"我的"模块本地数据备份与恢复功能说明。
> 本文档面向后续开发维护，不包含具体代码，仅说明功能行为与重点代码位置。

---

## 1. 功能概述

"我的" → "数据备份" 页面（`DataBackUpPage`）提供本地数据备份与恢复能力：

- **备份（导出）**：将本地数据库内容按指定范围、指定格式导出为文件，保存位置与文件名由用户在系统文件选择器中自行决定；同时支持通过系统分享面板直接分享导出文件。
- **恢复（导入）**：从本软件导出的 JSON 备份文件恢复数据，支持"清空后导入"与"覆盖导入"两种模式，恢复范围覆盖整个数据库。

核心设计原则：

- 金额以**元**为单位、两位小数存储与导出（数据库原值，不做 ×100 换算）。
- JSON 为**唯一恢复格式**（备份恢复专用），CSV / XLSX / PDF 为分析/报表用途，不做恢复。
- 导入解析与写库均在 IO 线程，清空模式为单事务原子操作。
- 备份 JSON 包含**整个软件数据库**：账单、记账天数、钱包、负债、愿望。

## 3. 导出（备份）功能说明

### 3.1 导出范围
- **全部账单**：读取账单表全量数据（按创建时间倒序）。
- **自定义日期范围**：日历组件选择起止日期，取 `[开始日 00:00, 结束日次日 00:00)` 区间内账单。
- 页面顶部实时显示当前范围内账单条数（预览）。

### 3.2 导出格式
| 格式 | 用途 | 特点 |
|---|---|---|
| CSV | 用户分析 | UTF-8 BOM；表头含日期/类型/种类/金额(元)/备注/钱包/关联负债 ID；末尾收支合计 |
| JSON | 备份恢复 | `schemaVersion=1`；含完整字段与全部表数据；唯一可恢复格式 |
| XLSX | 分析/存档 | Kexcel 生成；"明细"与"汇总"两个 Sheet；金额单元格两位小数格式 |
| PDF | 打印/报表 | compose-to-pdf；A4 多页自动分页；中文+数字由 SmileySans 字体渲染；页眉页脚含 QRMoney Logo |

### 3.3 导出流程
1. 用户选择范围与格式。
2. 点击"导出"→ 系统文件选择器（CreateDocument）弹出，可重命名、选位置。
3. 确认后回调 Uri → ViewModel 在 IO 线程读取数据库、生成文件字节、写入 Uri。
4. 页面显示"导出成功/失败"状态卡片。

### 3.4 分享流程
点击"分享"→ ViewModel 生成文件字节 → 写入 App 缓存目录 → FileProvider 生成 content Uri → ACTION_SEND 调起系统分享。导出与分享共用同一套生成逻辑。

## 4. 导入（恢复）功能说明

### 4.1 导入前置校验
- 文件可读；JSON 可解析。
- `schemaVersion` 必须等于当前版本（1），否则拒绝并提示。
- `app` 字段必须为 `QRMoney`，拒绝非本软件来源的文件。
- 字段解析使用 `ignoreUnknownKeys`，可容忍未来版本新增字段。

### 4.2 两种导入模式
| 模式 | 行为 | 确认要求 |
|---|---|---|
| 清空后导入 | 单事务内先清空账单/钱包/负债/愿望四表，再写入备份全部内容；中间失败自动回滚 | 点击后弹二次确认框（显示当前账单条数，红色警示不可恢复） |
| 覆盖导入 | 各表按主键 ID REPLACE 覆盖写入；备份中未包含的数据保留 | 无 |

默认选中"覆盖导入"（更安全）。

### 4.3 恢复范围（全库）
- 账单表（QBillEntity，按 ID 保留原记录主键）
- 记账天数（QMyDateEntity，更新首行，无记录则插入）
- 钱包表（QWalletEntity）
- 负债表（QDebtEntity）
- 愿望表（QWishEntity）

### 4.4 兼容性
- **旧版备份文件**（缺少 wallets/debts/wishes/myDate 字段）：可正常导入，缺失部分不写入（账单照常恢复，其他表保留现状）。
- **新版备份文件**被旧版本 App 读取：`ignoreUnknownKeys` 保证不报错（未做兼容测试，后续如需可考虑）。

## 5. 备份 JSON 数据结构（schemaVersion = 1）

顶层字段（字段缺失均有默认值，向后兼容）：

| 字段 | 类型 | 说明 |
|---|---|---|
| schemaVersion | Int | 固定 1，导入校验依据 |
| app | String | 固定 "QRMoney"，来源校验依据 |
| exportedAt / scope / startMillis / endMillis | — | 导出元信息 |
| billCount / summary | — | 账单条数与收支汇总（收入/支出/净额，元） |
| bills | List | 账单明细（id、amount、type、category、remark、createdAt、updatedAt、walletId、walletType、debtId） |
| myDate | Object? | 记账天数起点（firstLaunchDate、transactionCount） |
| wallets / debts / wishes | List | 钱包、负债、愿望全量实体数据（实体字段直出，枚举为名称） |

## 7. 关键设计决策与已知坑（维护必读）

1. **金额单位**：数据库与导出统一为"元、两位小数"；历史上曾按规范用"分"（Long ×100）实现，被用户否决。汇总计算用"分"整数累加再转元，避免浮点误差（见 `ExportModels.kt` 的 toExportPayload）。
2. **PDF 中文数字乱码根因**：曾用 DroidSansFallback.ttf，为纯 CJK 回退字体、**不含 ASCII 数字字母**，导致数字渲染为乱码。换用 SmileySans（含 ASCII+中文）后修复。**新增 PDF 功能时勿换回纯 CJK 字体**。
3. **MediaStore 下载目录导出**：插入后无实际文件，已废弃；统一走 SAF（CreateDocument）由用户自选位置。
4. **跨表事务**：清空模式用 `room-ktx` 的 `withTransaction` 包住全部表的清空+写入；单表 replaceAll*（DAO 内 @Transaction）保留但主流程不再单独使用。
5. **schemaVersion 兼容策略**：新增备份字段时**保持版本号不变 + 新字段给默认值**，保证旧文件可导、新字段可缺省；若未来做破坏性结构变更再升版本号。
6. **记账天数恢复**：天数由首次启动时间推算；恢复时"更新首行，无记录才插入"（曾因每次插入新行导致恢复失效，已修复，勿改回）。
7. **Hilt 版本联动**：Kotlin 2.4.x 需 Hilt ≥ 2.60.x（旧版 2.59 报 kotlin-metadata 版本不支持）；compileSdk 需 ≥ 37（compose-pdf 0.9.0 要求）。

## 8. 后续开发规划

### 8.1 近期：支付宝账单导入（自动识别）
- **数据格式**：支付宝"账单导出"CSV（含"交易时间/交易分类/收/支/金额/备注"等列，UTF-8，带 BOM 或 GBK）。
- **规划要点**：
  - 扩展导入入口：页面新增"从支付宝导入"（或导入卡片内分 Tab）。
  - 新增解析器（建议新建 `Feature_My/.../backup/` 下 `AlipayImporter.kt`）：读取 CSV → 表头识别/列名映射 → 金额与方向解析（"收入/支出/不计收支"）→ 分类归一化（支付宝类目 → App 内 category）→ 生成 QBillEntity 列表。
  - 复用现有导入写库通道：`DataBackUp_RT.importAllData`（覆盖模式即可，按 id=0 新插入）；必要时增加"仅导入账单，不动其他表"的写库入口。
  - 编码处理：优先 UTF-8，GBK 需按编码探测（支付宝导出文件常见 GBK/ANSI）。

### 8.2 近期：微信账单导入（自动识别）
- **数据格式**：微信"账单导出"CSV（表头"交易时间/交易类型/交易对方/商品/收/支/金额/当前状态"等，文件通常为 UTF-8 带 BOM）。
- **规划要点**：
  - 新建 `WechatImporter.kt`：列名映射（微信"金额"为文本可含符号，"收/支"列区分方向，含"已全额退款"等状态行需过滤）→ 映射为 QBillEntity。
  - 与支付宝导入共用：格式探测（首行/表头关键词识别支付宝或微信）、映射配置、导入结果预览（条数、时间范围、金额合计）后再确认写入。

### 8.3 通用：第三方账单导入框架
- 建议抽象 `BillImporter` 接口 + 各来源实现（Alipay / Wechat / 通用 CSV / 本软件 JSON），由统一入口（页面新增"账单导入"卡片或复用导入区）调度。
- 通用 CSV 解析（本软件导出的 CSV 亦可回导）可作为后续低成本扩展。
- 导入前提供**预览页**：识别出的账单条数、时间范围、收支合计，用户确认后写入；含"追加导入（id 新插入）"与"按时间去重"选项。

### 8.4 中期：备份体验增强
- 自动备份（定时/退出时自动导出到应用专属目录 + 下次启动可恢复）。
- 云同步占位（"我的"页已有入口"开发ing"），后续可接入云盘保存备份文件。
- 备份文件加密（可选，密码保护的 JSON）。
- 恢复前预览：解析备份文件后展示概要（各表条数、时间范围、天数）再确认写入。

### 8.5 长期
- schemaVersion 升级机制与多版本迁移（版本化导入）。
- 备份文件跨设备迁移（导出 → 新设备恢复全库，含钱包/负债/愿望/天数）。
- 导出格式扩展（如财务软件兼容格式），以 JSON 为源、各格式独立生成。
